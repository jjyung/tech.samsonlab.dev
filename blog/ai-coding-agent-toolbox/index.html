AI Coding Agent 工具箱：從選 Agent、搭配 Skills 到介面設計、程式碼理解與安全審查

使用 Coding Agent 寫程式，除了選擇 Agent 本身，還可以搭配 Skills、程式碼分析、架構圖和多工作目錄工具。這份清單依開發工作階段整理工具，主要根據專案公開資料，尚未逐項實測；實際導入前，建議先確認功能、授權與適用情境。

GitHub Star 數除另有註明外，為 2026 年 11 月 19 日 透過 GitHub API 查詢的快照，會隨時間變動。Star 數只能反映關注程度，不代表品質或安全性。

Agent 管理與平行開發

工具GitHub Stars一句話建議
T3 Code65,306想透過圖形介面管理 Coding Agent 的任務和進度，可以看看 T3 Code。
Multica56,626需要把人員、Agent 和任務放進同一個協作空間時，可以評估 Multica；使用前請確認其額外授權條件。
Herdr52,342（2026 年 11 月 23 日）同時跑多個 Coding Agent 時，可以在同一個終端機切換工作階段，查看哪些 Agent 還在跑、哪些已經完成。
Worktrunk12,625同時讓多個 Agent 處理不同任務時，用它管理 Git worktree 和隔離工作目錄。

Herdr 管理終端機工作階段，Worktrunk 管理 Git 工作目錄。可以讓不同 Agent 在各自的 worktree 工作，再用 Herdr 查看執行狀態。

Multica 的專案文件將它描述為 source-available，其授權在 Apache 2.0 文字之外另有條件；因此與本清單其他標準開源授權專案分開看待。

Matt Pocock’s Skills 裡的 grill-me 會針對想法或需求持續追問，協助你在開始實作前釐清尚未決定的問題。適合用在需求模糊、需要先討論取捨的時候；上表的 Star 數是整個儲存庫的數字，不是這個 Skill 的獨立數據。

Context／Token 管理

工具GitHub Stars一句話建議
Caveman121,326想讓 Agent 的回覆更短、減少輸出 token 時，可以試試 Caveman。
RTK87,133想精簡開發指令輸出以減少 Context 消耗時可以試用；排查問題時仍應確認是否需要完整輸出。
Headroom80,122想透過 Library、Proxy 或 Agent wrapper 壓縮工具輸出與訊息內容時可以評估；實際效果與原文取回能力取決於整合方式。

RTK 主要從 Shell 指令輸出切入，也提供可選的 API proxy；Headroom 則提供較通用的 Context 壓縮層。兩者的處理範圍可能重疊，搭配使用前應測試資訊保留和任務結果，不宜直接將節省比例相加。

RTK 的 rtk-oss 版本採 Apache 2.0；完整 rtk 和 rtk-proxy 包含 BUSL-1.1 元件，使用前應確認各版本授權條件。

開發

開發流程與規格驅動

工具GitHub Stars一句話建議
Superpowers321,473想把需求釐清、規劃、實作和審查串成一套開發流程時可以試用；實作採用 TDD，小任務需留意流程成本。
Spec Kit150,544想從規格一路拆出計畫與任務，再交給 Agent 實作時可以試用；團隊也需要維護這些產物。
OpenSpec75,216想以每次變更為單位，把規格、任務與實作串起來時可以試用，也適合在既有專案評估。
BMad Method55,531需要涵蓋分析、規劃與實作的完整流程時可以參考，不一定要整套導入。

Superpowers 把多個 Skills 串成開發流程：先透過 brainstorming 確認需求與設計，再拆解實作計畫；實作時採用 TDD 的 Red-Green-Refactor 循環，並搭配程式碼審查與完成前驗證。它也提供 Git worktree 和子代理協作的流程，但實際使用時仍要確認 Agent 的支援情況，並留意流程帶來的時間與 token 成本。

Spec Kit 以規格驅動開發為入口，透過專案原則、規格、計畫與任務等產物，讓人與 Agent 逐步確認要做什麼、如何實作。它也提供獨立的除錯與構想評估擴充。

實作、審閱與回饋

工具GitHub Stars一句話建議
Ponytail194,087希望 Agent 寫新程式前先考慮既有功能與較簡單解法時，可以加入這組 Skills。
Open Code Review54,242想用專門的審查流程分析 Git 差異或掃描檔案時可以試用；結果仍需人工判斷。
Plannotator13,549想在瀏覽器標註 Agent 的計畫、文件或程式碼差異，並將意見送回 Agent 時可以試用。

Open Code Review 結合規則、固定的審查步驟與 AI Agent，也提供 Skills，讓現有 Coding Agent 參與審查。專案提供自行設定模型的原生模式，以及使用既有 Agent 模型與驗證方式的委派模式；兩種模式的執行流程不同。

Plannotator 著重讓人審閱成果並提供回饋；它不是用來取代 T3 Code 或 Multica 的 Agent 管理介面，也可與 T3 Code 整合。

Codex Security14,148想掃描程式碼、驗證疑似漏洞並協助產生修補方案時可以評估；模型使用與部分資安能力的存取條件另計。

Codex Security 提供 CLI、TypeScript SDK 與 Codex 工作流程，可掃描儲存庫、指定路徑或 Git 變更。它的 CLI 與 SDK 採 Apache 2.0 授權；模型服務的費用、資料處理方式與帳號資格仍須另行確認。掃描報告應檢查證據和排除範圍，不能視為沒有漏洞的保證。

怎麼開始？

不必一次裝完所有工具。先挑一個順手的 Coding Agent，再依眼前的工作補上需要的能力：要做介面就試 UI/UX Skill，需要理解專案就看 Graphify。要平行處理任務，可以用 Worktrunk 隔離工作目錄，或用 Herdr 查看各 Agent 的執行狀態。

安裝第三方 Skills 前，先閱讀其指示、腳本與權限需求；工具如何呼叫模型、處理程式碼與執行指令，也應依專案敏感度確認。
